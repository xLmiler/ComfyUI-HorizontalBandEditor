# ComfyUI-HorizontalBandEditor

一个用于 **ComfyUI 横向截面编辑、文字面板替换、表图/里图 WebP 合成，以及从合成 WebP 中提取里图** 的自定义节点插件。

---

## 当前节点

插件当前只保留 3 个节点：

| 节点 | 分类 | 用途 |
|---|---|---|
| `横向截断面板编辑器` | 图像/编辑 | 删除多个横向截面并自动拼接，或使用文字面板替换截面 |
| `表里图合并编辑器` | 图像/保存 | 将表图与里图合成为单个动画 WebP，并按选择写入 ComfyUI 工作流元数据 |
| `读取WebP里图` | 图像/加载 | 读取由本插件生成的表里图 WebP，并只输出其中的里图帧 |

已移除旧的：

- 保存编辑图像（继承源图工作流）
- 加载带元数据图片
- 保存工作流JSON
- 保存里图媒体
- 预览 WebP 图片

当前工作流尽量直接使用 ComfyUI 自身的图片节点和 WebP 拖入能力。

---

# 安装

将插件目录放到：

```text
ComfyUI/custom_nodes/ComfyUI-HorizontalBandEditor/
```

安装或覆盖更新后：

1. 重启 ComfyUI
2. 浏览器执行一次：

```text
Ctrl + F5
```

# 1. 横向截断面板编辑器

用于在一张图片中同时编辑多个横向区域。

## 输入

### 输入图像

```text
IMAGE
```

可以连接：

- Load Image
- VAE Decode
- 其他 IMAGE 输出

### 输入透明遮罩

可选：

```text
MASK
```

---

## 横向截面

最多支持：

```text
12 个截面
```

对应：

```text
A B C D E F G H I J K L
```

每个截面始终横跨完整图像宽度，只需要确定：

```text
上边界
下边界
```

通过：

```text
截面数量
编辑截面
```

控制当前使用的截面数量与正在编辑的截面。

---

## 可视化拖拽

节点底部提供图像编辑预览。

支持：

- 在空白区域拖拽：重新创建当前截面
- 拖动上边缘：调整截面上边界
- 拖动下边缘：调整截面下边界
- 拖动截面内部：整体上下移动
- 点击其他截面：切换当前编辑截面

预览区域会随着节点大小自动缩放。

---

## 删除模式

当：

```text
启用文字面板 = 关闭
```

选中的横向截面会被删除。

例如：

```text
保留 A
删除 1
保留 B
删除 2
保留 C
```

处理后：

```text
保留 A
保留 B
保留 C
```

剩余部分自动纵向拼接。

---

## 文字面板模式

当：

```text
启用文字面板 = 开启
```

截面不会被删除，而是替换为文字面板。

支持：

- 纯色背景
- 透明背景
- 背景颜色
- 文字内容
- 文字颜色
- 字体名称或字体完整路径
- 字号
- 内边距
- 行距
- 水平对齐
- 垂直对齐

如果文字需要的高度超过原截面高度：

```text
输出图像会自动增加高度
```

不会强制裁掉文字。

---

## 调色盘

当前以下参数支持直接点击调色盘选择颜色：

```text
背景颜色
文字颜色
```

同时保留十六进制输入，例如：

```text
#FFFFFF
#000000
#FF80C0
```

---

## 动态显隐

关闭文字面板时，文字相关参数自动隐藏。

当：

```text
面板背景 = 透明
```

时：

```text
背景颜色
```

自动隐藏。

切换编辑截面时，只显示当前截面的上下边界参数。

---

## UI 兼容

插件使用 ComfyUI 原生 Widget 为主。

支持：

- 经典节点 UI
- Nodes 2.0

不提供独立 UI 模式切换，是否启用 Nodes 2.0 由 ComfyUI 全局设置决定。

---

## 输出

```text
RGB图像
透明遮罩
RGBA图像
宽度
高度
源图文件名
继承源图工作流
```

# 2. 表里图合并编辑器

用于将：

```text
表图
+
里图
```

合成为一个真正的动画 WebP 文件。

---

## 输入

### 里图

必需：

```text
IMAGE
```

支持：

- 单张图片
- IMAGE Batch
- 多帧动画解码结果

新版 ComfyUI 的图片输出节点本身可以处理 IMAGE 图片组，因此多帧里图可以直接参与后续处理。

---

### 表图

可选：

```text
IMAGE
```

如果未连接表图，则自动生成纯色表图。

---

## 表图占位颜色

当表图未连接时使用。

支持：

```text
调色盘选择
+
十六进制手动输入
```

例如：

```text
#FFFFFF
```

---

## 表图连续帧数

用于决定最终 WebP 开头连续多少帧为表图。

例如：

```text
表图连续帧数 = 2
```

最终帧结构：

```text
第 1 帧：表图
第 2 帧：表图
第 3 帧：里图第 1 帧
第 4 帧：里图第 2 帧
...
```

插件会把：

```text
里图起始帧
里图帧数
```

写入 WebP 内的 HBE 标记，供 `读取WebP里图` 节点使用。

---

## 表图尺寸处理

表图默认执行：

```text
等比例缩放
+
居中裁剪
+
铺满里图尺寸
```

不提供额外“是否裁剪”开关。

---

## 重复帧保护

某些 WebP 编码器可能合并完全相同的连续帧。

为了保证：

```text
表图连续帧数
```

与真实 WebP 帧结构一致，插件会对重复帧进行几乎不可见的微小像素差异处理。

---

## WebP 质量

```text
1 - 100
```

当：

```text
无损 = False
```

时生效。

---

## 无损

开启：

```text
无损 = True
```

时使用 WebP lossless 编码。

---

# 元数据来源

可选择：

```text
图片内置元数据
当前工作流元数据
不保存元数据
```

## 图片内置元数据

使用里图源文件中原本保存的 ComfyUI：

```text
prompt
workflow
其他元数据
```

再按照 ComfyUI WebP 元数据结构写入最终 WebP。

适合：

```text
希望最终 WebP 携带里图原本的工作流
```

---

## 当前工作流元数据

使用 ComfyUI 当前执行时提供的：

```text
PROMPT
EXTRA_PNGINFO
```

适合：

```text
希望最终 WebP 携带当前正在执行的完整 ComfyUI 工作流
```

---

## 不保存元数据

不写入：

```text
prompt
workflow
```

但仍会保存最小 HBE 帧结构标记，以便后续读取里图。

---

# WebP 直接拖入 ComfyUI

当前插件保留 WebP workflow 拖入兼容逻辑。

正常流程：

```text
表里图合并编辑器
↓
生成 .webp
↓
从 Windows 文件管理器直接拖入 ComfyUI 画布
↓
恢复对应 workflow
```

因此不需要额外的“加载元数据”节点来恢复工作流。

---

## 输出

```text
图像
WEBP文件路径
```

### 图像

最终 WebP 全部帧组成的 IMAGE Batch。

### WEBP文件路径

真正保存到磁盘的 `.webp` 文件路径。

# 3. 读取WebP里图

这是一个专门用于**解包表里图 WebP** 的轻量节点。

它只做一件事：

```text
读取由“表里图合并编辑器”生成的 WebP
↓
读取内嵌 HBE 帧标记
↓
定位里图起始帧
↓
只输出里图 IMAGE
```

---

## 输入

```text
WebP文件
```

使用图片上传/选择控件选择一个 `.webp`。

节点只接受 WebP。

如果 WebP 不是由本插件生成，且没有 HBE 表里图标记，会直接提示无法确定里图起始帧。

---

## 输出

节点只有一个输出：

```text
里图
```

类型：

```text
IMAGE
```

没有：

- MASK 输出
- 元数据字符串输出
- 文件名输出
- workflow JSON 输出
- 其他辅助输出

---

## 多帧 / GIF 里图

如果原始里图在合并时是多帧：

```text
Frame 1
Frame 2
Frame 3
...
```

`读取WebP里图` 会把这些里图帧作为一个 IMAGE Batch 直接输出。

因此在新版 ComfyUI 中可以直接作为：

```text
图片组
```

继续接到支持图片组的输出/处理节点。

这也适用于原本由 GIF 解码得到的多帧里图。

节点本身不会另外生成 GIF 文件；它输出的是 ComfyUI 的多帧 IMAGE 数据。

---

# 性能设计

`读取WebP里图` 沿用此前已经验证过的性能优化逻辑：

1. 元数据只读取一次
2. 图像帧优先使用 ComfyUI 原生 `LoadImage` 解码
3. 不生成额外 UI 动画预览
4. 不复制完整第二份动画 Tensor
5. 里图通过 Tensor slice 直接取得
6. 不递归扫描整个 input 目录

这样可以避免早期“加载带元数据图片”节点造成的：

```text
动画加载后画布卡顿
切换工作流变慢
其他图片节点缓存显示延迟
```

# 推荐工作流

## 横向编辑

```text
Load Image
↓
横向截断面板编辑器
↓
ComfyUI 原生图片输出节点
```

---

## 合成表里图 WebP

```text
表图（可选） ─────┐
                  ↓
              表里图合并编辑器
                  ↑
里图 ─────────────┘
```

---

## 从 WebP 重新提取里图

```text
表里图 WebP
↓
读取WebP里图
↓
IMAGE / 图片组
↓
ComfyUI 原生图片输出或其他处理节点
```

# 当前设计原则

- 插件只保留 3 个核心节点
- 能交给 ComfyUI 原生节点完成的事情，不额外增加辅助节点
- WebP workflow 恢复优先使用“直接拖回 ComfyUI”
- `读取WebP里图` 只负责拆出里图，不承担元数据浏览器功能
- 多帧直接使用 ComfyUI IMAGE Batch / 图片组
- 参数 UI 尽量使用 ComfyUI 原生 Widget
- 自定义前端只处理必要的拖拽、预览、显隐、调色盘和 WebP workflow 兼容

---

# 当前限制

- 多个横向截面目前共用同一套文字样式和文字内容
- `读取WebP里图` 只用于带有 HBE 表里图标记的 WebP
- 多帧输出是 ComfyUI IMAGE Batch，不是直接生成 GIF 文件
- 表图占位颜色只在没有连接表图时生效
